## Result

Claude updates itself with Squirrel.Mac.

## Findings

- Failure mode: Squirrel downloads a new build and replaces the *whole* Contents directory of the bundle it is running from. In a clone that removes the rewritten Info.plist, the numbered icon, the shim, the renamed `<exec>.real` — everything the clone's identity depends on. It also replaces the code, so our ad-hoc signature is gone; the new contents carry the vendor's signature and the bundle identifier reverts.
- Consequence for the user: the instance stops being numbered and rejoins the original's Dock tile. Its data directory is untouched, so nothing is lost.
- Response: the launcher records `builtFromSourceVersion` per instance, shows "update available" when the source moves ahead, and Rebuild regenerates the bundle from the new source *without touching the profile*. The original application is never modified by any of this.
- In every case: the *source* application is opened read-only. The builder fingerprints Contents/Info.plist and _CodeSignature/CodeResources before and after each build and refuses to report success if either changed.

## What a human must confirm

1. To observe this directly, leave a clone running until the vendor ships an update, then check whether the clone's Info.plist still carries MALGeneratedBy.
2. The behaviour is version-specific, so treat the finding above as the mechanism and the observation as confirmation.
